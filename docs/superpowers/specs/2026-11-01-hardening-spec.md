# Resume Studio Hardening Spec (2026-11-01)

## Context

A full read-only audit of the repository found that the PDF pipeline, data model, and
core UX are sound, while a set of integrity, privacy, documentation, and maintainability
defects need correction. This document is the requirements source for
`docs/superpowers/plans/2026-11-01-resume-studio-hardening.md`.

## Verified baseline

Recorded on this machine on 2026-11-01:

- `npm run typecheck`: PASS (no output = no errors).
- `npm run lint`: PASS (no output = no errors).
- `npm run build`: PASS.
- `npm test`: 45 tests, 40 pass, **5 fail** with `ECONNREFUSED`.
  - The 5 failures are integration tests that call `http://127.0.0.1:8000` (3, Python ML)
    or `http://127.0.0.1:3000` (2, Next dev server). They fail when those services are
    not already running.
- `pdflatex` and `pdftotext` resolve on PATH from TeX Live 2025.
- Node 24.22.1, npm 12.2.1, Python 3.14.7. `pytest` is not installed; Python tests run
  as `python tests/test_ml_service.py`.
- Working tree is clean on branch `main`. Both reference PDFs are tracked by git, as are
  five `__pycache__/*.pyc` files.

## Goals

1. Make the test suite trustworthy and green without requiring live services.
2. Remove personal reference PDFs and generated bytecode from git tracking; provide a
   history-cleanup runbook without executing it.
3. Eliminate fabricated claims from the ML fallback and expose when fallback is in use.
4. Fix ML service correctness and hygiene defects.
5. Make PDF/A labeling truthful: the current toggle adds metadata only.
6. Align LaTeX ZIP export photo handling with the compile route.
7. Adopt Zod for shape validation without changing acceptance, rejection, or error text.
8. Fix broken/missing UI CSS and theme inconsistencies; improve menu/modal dismissal.
9. Reduce `src/app/studio.tsx` to focused hooks/components without behavior change.
10. Make README/ROADMAP/architecture documents match the implementation.

## Non-goals

- Changing resume content, PDF layout, template visual output, or page-fit behavior.
- Renaming persisted fields (`pdfaCompliant`, IndexedDB keys, backup version 2).
- Adding cloud services, telemetry, authentication, or new PDF engines.
- Replacing `pdflatex` or changing the security model of the compile route.
- Adding React component-test infrastructure (no jsdom/testing-library) in this pass.
- Rewriting git history automatically (documented runbook only).
- Implementing real embeddings, spaCy NER, or model fine-tuning.

## Requirements

### R1 — Self-contained tests

- `npm test` must exit 0 with no services running.
- Tests that genuinely require the Python service must skip with an explicit reason.
- The export-tex route tests must call the route handler directly, not over HTTP.
- `npm run verify` must run typecheck, lint, JS tests, Python tests, and build.

### R2 — Privacy

- `git ls-files` must contain no `*.pdf` reference files and no `__pycache__` files.
- Local copies remain available in a gitignored `reference/` directory.
- A written runbook explains history rewriting and its consequences; it is not executed.

### R3 — ML fallback integrity

- `generate_rule_based_fallback` must not invent percentages, outcomes, or activities.
- It may strengthen verbs and add a visibly marked placeholder that asks for a real metric.
- The UI must label fallback output as rule-based and warn that the metric must be verified.

### R4 — ML service correctness

- No `typing.Any` misuse; no capture-group bug in phone extraction.
- Date validation must not depend on a hard-coded 2020–2026 year list.
- Errors must be logged server-side and not leak raw exception text to clients.
- Request bodies must have explicit size/length limits.
- `train_ner.py` documentation must state that it generates a synthetic benchmark and
  does not train a model.

### R5 — Truthful PDF/A labeling

- UI copy must say metadata tags, not certification.
- The persisted `pdfaCompliant` field name stays for backup compatibility.

### R6 — Export parity

- ZIP export must support the same photo formats as compile (PNG, JPEG, PDF).
- Exported `main.tex` must reference the extracted asset path deterministically.
- An exported ZIP must compile standalone with local `pdflatex`.

### R7 — Zod validation

- Shape validation uses Zod schemas.
- Project-level referential integrity checks and all existing error messages remain.
- `validateProject`, `migrateProject`, and `resolveVariant` signatures do not change.
- Unknown keys survive import/export because validation remains predicate-only.

### R8 — UI correctness

- Page-Fit modal must render with a backdrop, centered card, and reachable footer.
- Undefined `fadeIn` keyframes/`animate-fade-in` and the dead `sidebar-hidden` class must be fixed. `--shadow-xs` is supplied by Tailwind v4 and is not a defect.
- Modals that ignore the theme must use semantic tokens, except intentionally dark code
  panes which must be documented in code comments.
- Menus close on outside click and Escape; modals close on Escape and restore focus.

### R9 — Decomposition

- `studio.tsx` shrinks below 1,100 lines through mechanical extraction.
- Compile/preview, autosave, and drag state move to hooks; topbar and preview move to
  components. No state library is introduced.
- Each extraction is a separate commit that passes the verify gate and browser smoke.

### R10 — Documentation truth

- README prerequisites and test instructions match Node 24 / pdflatex + pdftotext.
- ROADMAP no longer claims PyTorch, spaCy, sentence-transformers, fine-tuned NER, or
  Vitest; it describes the regex/lexical implementation and known limits.
- architecture.md reflects Zod and the current checklist state.

## Acceptance criteria

- `npm run verify` exits 0 on a machine with TeX Live and Python; without services,
  exactly the 3 ML HTTP tests are reported skipped and all others pass.
- `git ls-files` matches the privacy requirement.
- `python tests/test_ml_service.py` passes, including new fallback and ATS tests.
- Existing `tests/resume.test.mjs` passes without edits (except additive cases).
- All five templates still compile; links, selectable text, and overflow behavior are
  unchanged.
- A v1 backup and a v2 backup with an unknown future key both import without data loss.
- Manual browser matrix in the plan passes in light and dark themes at desktop and
  ≤960px widths.
